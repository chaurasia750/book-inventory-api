## 1. In one minute
After this plan an Owner can create, list, edit, activate and deactivate the items of their company, give each item several barcodes and a vendor, and Staff can look active items up; no company ever sees another's items. Try it: as an Owner `POST /api/v1/items` with a name and the category `BOOK` and get back `ITM-0001`; `GET /api/v1/items?search=<barcode>` finds it.

## 3. Approach
`Item` derives from `CompanyOwnedRoot`; `ItemBarcode` is a company-owned child (`CompanyOwnedChild`) kept like the school's classes: replacing the list keeps rows for kept barcodes, soft-deletes removed ones and adds new ones, and the unique index on `(company_id, barcode)` covers live rows only. The code comes from `ICompanyCodes` with prefix `ITM` (platform P23). Category, GST rate and the stock-managed default are value rules inside `ItemRules`/`ItemCategory`, written once. The vendor is checked and named through the vendor directory capability (vendor#03): on create or when the vendor changes it must exist and be active; the list asks the capability for vendor names and for the ids matching a search text. A duplicate barcode is checked by the use case (409) with the unique index as the backstop. Staff see active items only, applied in the query service like the school list.

## 6. Not verified

It is **not** applied to any shared database; the owner applies it there.
- The unique index on `(company_id, barcode)` as the database backstop for two parallel creations with the same barcode was not exercised (the use case's check was).
- The category of an item changing while stock exists (R15) cannot be exercised: no stock module exists yet.
- The check left 28 `I01 ...` test items in the two companies (B27 test data).

## 7. Risks and notes
The migration is additive (new schema and tables); rollback: drop schema `item`. The search by vendor name asks the vendor capability for ids first, so a vendor with very many matches makes a long id list; the capability caps it (vendor#03). If the owner answers Q1 with a managed category list, `ItemCategory` becomes a table and this plan changes before it starts.

## 1. In one minute
After this plan an invoice is made from a confirmed order for the quantities delivered now, numbered `INV/2026-27/0001`, posting the stock out and the school ledger debit in one transaction; the Owner cancels it with a reason, which reverses both. Try it: `POST /api/v1/school-orders/{id}/invoices`.

## 2. Touches / leaves out
Touches: `Domain/Sales` (`Invoice` with lines, built from an order through the R7 rule; cancel), `Application/Sales` (make and cancel use cases calling `IStockPosting` and `ILedgerPosting`, queries), persistence and migration (invoice tables), controller, catalogue, `docs/Code_Map.md`.
Leaves out: PDF (Q12), payments. Schema change: yes (invoice tables, additive; after sales#01).

## 3. Approach
The order hands out the deliverable quantities and records them (the one place that knows what remains); the invoice is built from the order line snapshots and the same R7 rule, including the sharing of rupee discounts of R8. The use case posts stock and ledger in the same transaction (D3) and fails as a whole. The number comes from the code series with the prefix `INV/<financial year>/`.

## 1. In one minute
After this plan an issued invoice can be handed out as an A4 PDF in the drawn format: the same header on every page (logo, full name, tagline, address, GSTIN, PAN, the title and the invoice number), the school's details on page 1, the lines with no per-line GST column, a **rate-wise GST summary**, the totals and the amount in words, and at the bottom of the last page the bank details, the terms and conditions and the signature, with `Page x of y` on every page. Try it: `GET /api/v1/invoices/{id}/pdf` opens the PDF in the browser.

## 3. Approach
The PDF is built from the invoice and its snapshot (R28): when an invoice is made it also snapshots the company's printed identity (name, tagline, address, mobile, email, GSTIN, PAN, state, bank account, terms, footer) and the school's address (D7, R33), so a reprint never changes when either is edited; the logo and signature are read live (cosmetic). The document is **HTML + CSS** rendered by **Scriban** (already in the solution) into the drawn A4 layout, then handed to `IHtmlToPdfRenderer` (platform#09) with A4, `printBackground`, the **same compact header as `HeaderHtml`** (inline styles and the logo as a data URI, with the top margin sized to it, so it repeats on every page), and a **footer template** with the invoice number, the school and `Page x of y` (R30). The column header repeats through the table head; rows never split; the closing block has `break-inside: avoid`, so it moves whole to one more page when it does not fit. The GST is summed **by HSN and rate** into the summary rows only when GST is on, never per line (R32, D7); the computation is untouched (R7). The layout (R26) is the `?layout=BOOK_LIST|BY_CLASS` parameter or the school's default. A renderer failure is `500 document.render_failed` (R28). The PDF is rendered on demand, never stored (Q18). Amount in words is one domain helper in Indian numbering.

## 7. Risks and notes
Additive migration `Sales_InvoiceSnapshot` (18 columns on `sales.invoice`, `company_print_gstin` default true) with a one-time backfill of the 12 invoices of the local database from the company and school, applied to the local `book_inventory` after its SQL was shown; rollback: drop the added columns. Found while building: the company's bank account had no format check and duplicated the vendor's, fixed by company#09 (the shared `BankAccount`). The browser path comes from the platform setting (platform#09); a wrong path is the way to check the failure row. The page-level checks (page count, the text of each page, the closing block on one page) read the PDF with `pypdf`, installed only in the scratch Python used for checks, never added to the solution. The first-page and later-page headers are the same on purpose: a Chromium repeating header is one template for every page.
